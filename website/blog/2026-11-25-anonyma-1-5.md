Since 1.3.0, anonyma has had seven releases of the library, and five more packages have had their
first releases: a pool of worker threads, an engine on a Rust core for Node.js, and anonyma for
Python, Go and any language through a sidecar. This post says what changed, why, what to check when
you upgrade from 1.3, and what we learned on the way.

<!-- truncate -->

## Upgrading from 1.3: check `rules` with a preset

One change can alter your output. Up to 1.3, `rules` given with a preset took the place of the
preset's rules, and a non-empty list of rules was also the list of categories replaced. A single
rule could therefore switch off the rest of a preset:

```ts
import { anonymize } from "anonyma";

anonymize("Card 4111 1111 1111 1111, mail ana@example.com", {
  preset: "pci-dss",
  rules: [{ category: "email", strategy: { strategy: "redact", label: "[EMAIL]" } }],
}).text;
// 1.3: "Card 4111 1111 1111 1111, mail [EMAIL]"   the card number stayed in clear
// 1.4: "Card ***************1111, mail [EMAIL]"   the preset still masks it
```

Since 1.4.0, `rules` adjust a preset: they override the strategies of the categories they name and
add the categories the preset does not cover. That is what people expected of a preset
([#47](https://github.com/izaccavalheiro/anonyma/issues/47)), and it is the safe reading for a
library whose job is to leave nothing behind. Without a preset, `rules` still list the
categories replaced. If you combined the two, compare your output before and after the upgrade.

The same release keeps card numbers whole: the separator after a card number written in groups is no
longer part of the match ([#48](https://github.com/izaccavalheiro/anonyma/issues/48)), and twelve of
its digits are no longer mistaken for an Aadhaar number
([#49](https://github.com/izaccavalheiro/anonyma/issues/49)).

Nothing else changes what you get back. The rest of this post is about speed and reach.

## Batches cost less

Most data that needs scrubbing comes as many short texts: log lines, rows, chat turns. On a
200-character line, the fixed cost of a call — starting the detectors and resolving what they
found — is most of the work. 1.5.0 pays it once per batch:

- `detectBatch()` and `anonymizeBatch()` join the entries under 8 KB into texts of about 32 KB, with
  a separator that no detector matches across, scan each once, and split the matches back by entry.
  The results are those of one call per entry; 745 lines of 100 KB take 44 ms instead of 113.
- `Pipeline.scanBatch()`, `transformBatch()` and `transformBatchAsync()` do the same for compiled
  pipelines of `anonyma/engine`.
- Detectors skip the patterns that count only after a label (account, member and record numbers,
  ten national-ID formats) when the text has no such label. `detect()` on 1 KB without labels takes
  about a third less time.

1.5.1 finds the label before a candidate value by binary search, so text with many labels and many
values no longer costs labels × values.

Some entries are still scanned one by one: those that start with a greeting word ("Dear", "Hi"),
hold a NUL character or are 8 KB or longer, and every entry when you pass a custom detector. The
promise is the results of one call per entry, and the joined scan is used only where it keeps it.

## Every core: `anonyma-parallel`

A batch function runs in the calling thread. `anonyma-parallel` (0.1.0, published with 1.5.2) cuts
large batches into chunks of about 256 KB, runs each with anonyma's own batch function on a pool of
worker threads, and returns the results in input order:

```ts
import { createPool } from "anonyma-parallel";

const pool = createPool(); // one worker per core but one; create it once and keep it
const results = await pool.anonymizeBatch(lines, { preset: "gdpr" });
await pool.close();
```

On a 4-core laptop, 4,096 log lines (0.8 MB) take 67 ms on seven workers instead of 227 ms in one
thread. A batch under 8 KB stays in the calling thread, where it costs less than the trip to a
worker, and `pool.explain(lines)` tells you which way a batch will go. Options cross to the workers,
so they cannot hold functions: custom detectors and plugins stay with anonyma itself.

## A Rust engine for Node.js: `anonyma-native`

`anonyma-native` 0.1.0 runs detection and anonymization on anonyma's Rust core, prebuilt for Linux,
macOS and Windows, with anonyma's result shapes and offsets:

```ts
import { createEngine } from "anonyma-native";

const engine = createEngine({ preset: "gdpr" }); // build once, reuse
const results = engine.anonymizeBatch(lines); // as anonymizeBatch(), on every core
```

On the same laptop it is 2.4 to 2.9 times faster than anonyma on single texts and 7 times on
batches of log lines. It runs built-in detectors, presets, rules and default strategies; custom
detectors and patterns, allowlists, plugins and the span engine stay with anonyma, which is also
faster when only a few categories are detected.

It is opt-in on purpose. The first measurement of the core from Node.js found the addon less than
twice as fast where it won at all, which did not justify a native binary per platform in a package
without dependencies, and the decision was recorded with its numbers. After the core's speed work it
reached two to three times on `anonymize()` with a preset, so it was published, as a separate
package that `anonyma` never imports.

## Beyond JavaScript

The Rust core (`crates/anonyma-core`) ports the TypeScript library: all 27 categories, every
checksum validator and preset, vault tokens, receipts and the span engine's `scan`. One conformance
suite of 284 cases runs against the TypeScript reference and against every binding, so they all
return the same results.

- **Python** (`pip install --pre anonyma`, alpha): prompt shielding and restoration, batches with
  the GIL released, pandas and Polars columns in one call, and OpenAI, Anthropic and LangChain
  integrations.
- **Go** (`go get github.com/izaccavalheiro/anonyma-go@latest`, alpha): an `Engine` built once and
  safe for concurrent use, batches on every core, an `io.Reader` and `net/http` middleware, with the
  core prebuilt for five platforms.
- **The sidecar** (`ghcr.io/izaccavalheiro/anonyma-sidecar`, 0.2): the TypeScript library as a local
  HTTP and MCP service for any language, with batch endpoints where a text costs about a twelfth of
  a request of its own.

Building the core paid off for JavaScript too. Benchmarking it against the TypeScript engine found
that `anonymize()` and `tokenize()` copied the whole text for every value they replaced: a megabyte
with the `gdpr` preset took up to 8 seconds. 1.3.3 assembles the output once, in time linear in the
length of the text, with the same output.

## What we learned

- **Benchmarks find what tests cannot.** Three of the costs that grew with text length times matches
  were found by comparing engines, not by a failing test: every result was right. CI now checks that
  the span engine stays linear, and times every pull request to `main` against its base.
- **Measure, decide, write the numbers down.** Recording why the native addon was declined is what
  made it easy to publish once the numbers changed.
- **A fix that changes output is a change.** The 1.4 rules fix makes the library do what its
  documentation said, and it still changes what some callers get back. It comes first in the
  changelog and first in this post.

[History and decisions](/docs/project/history) has the longer story, from 1.0 to now, with the
reasons behind the project's main choices. The [changelog](/docs/project/changelog) lists every
change, and the [releases page](/docs/project/releases) the latest version of every package.
